# MIPT_router_bot

Telegram-бот для учёта роутеров общежития № 7. Один процесс Node.js, SQLite как рабочая база, Google Sheets как редактируемое сотрудниками представление текущего учёта. Интерфейс на русском, только в личных чатах.

**Настоящие Telegram и Google API из приложения ещё не проверены:** токен бота и ключ сервисного аккаунта не предоставлены. Исходная таблица при разработке только прочитана, её данные и оформление не менялись. Автоматические проверки используют отдельные синтетические данные и подмены внешних сервисов.

## Возможности

- Доступ по числовому Telegram user_id: администратор, оператор, наблюдатель; отзыв действует на открытые диалоги и старые кнопки. Последний администратор защищён от удаления.
- Постоянные карточки, уникальные инвентарные номера, проверка нормализованных MAC и серийных номеров; поиск, фильтры и страницы.
- Выдача, физический возврат, продление, связанная передача и замена, утрата, обнаружение, проверка, ремонт, списание, VIP и отдельные исключения из сбора.
- История выдач и неизменяемый через приложение журнал; корректирующие события вместо удаления истории. При зависимых событиях слепой откат запрещён.
- Транзакционные изменения, версия карточки, уникальная действующая выдача и ключи повторных операций.
- Исходящая очередь Sheets, повтор после сбоя, проверка ручных правок перед каждой записью, `/sync` с трёхсторонним сравнением и разбором конфликтов.
- `/repair_colors`: предварительный просмотр и восстановление распознанных правил условного форматирования, сохранение Checked и постороннего оформления.
- Кампании с предварительным просмотром, очередью обхода, ответственными, исключениями и устойчивыми к перезапуску напоминаниями сотрудникам.
- Отчёты, подсчёт выдач за период отдельно от физических устройств, CSV с защитой от формульной инъекции, резервное копирование.

## Проверка без токенов

Рекомендуемый выпуск — **Node.js 24.22.2 LTS**, закреплён в `.node-version` и CI по официальному архиву на 07.11.2026. Проверяется также нижняя граница 24.12.0 (установленная в рабочей среде), npm 11.6.2. Поддерживается ветка Node 24 от 24.12.0. `node:sqlite` в нижней проверенной версии отмечен средой как экспериментальный: предупреждение ожидаемо. Перед заменой версии Node прогоните тесты и восстановление копии.

```sh
npm ci
npm run check
npm test
npm run demo
```

Демо работает в памяти, не пишет в настоящую таблицу и никому не отправляет сообщения. Для разработки не нужны Python, Docker, сервер БД или установка браузера.

Единственная прямая зависимость во время работы — официальная `google-auth-library` **11.3.3**. Для разработки отдельно закреплён Prettier **3.9.10** (`npm run format`). Все транзитивные версии закреплены в `package-lock.json`. Telegram использует документированный HTTPS Bot API через встроенный `fetch`; SQLite, тесты и резервное копирование — стандартные средства Node. Google OAuth намеренно поручен официальной библиотеке.

## Запуск бота

1. Создайте бота через [@BotFather](https://t.me/BotFather), сохраните токен вне Git.
2. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN` и `BOOTSTRAP_ADMIN_ID`. Используйте постоянный числовой ID, не username. Неавторизованному пользователю бот сообщает только его собственный ID.
3. Сначала оставьте `SHEETS_MODE=disabled`, используйте отдельную тестовую БД.
4. Запустите `npm start`, откройте личный чат с ботом и отправьте `/start`.
5. В «Настройки → Доступ» назначьте операторов. Для получения уведомлений сотрудник должен сначала открыть чат с ботом.
6. Подключайте Google только по [инструкции подключения](docs/GOOGLE_SHEETS.md). Для постоянной работы используйте один процесс и постоянный диск.

В `disabled` операции сохраняются в БД и исходящей очереди. В `memory` интерфейс использует демонстрационную таблицу, которая исчезает при остановке; этот режим явно помечен в меню. В `google` используются настоящие API и данные.

Основные команды: `/menu`, `/help`, `/find текст`, `/list`, `/reports`, `/collection`, `/export`. Для администратора: `/settings`, `/sync`, `/repair_colors`, `/provision`. Операции удобнее выполнять кнопками в карточках. Любая существенная операция завершается экраном подтверждения; «Отмена» до подтверждения не меняет учёт.

## Перед настоящим запуском

Владелец учёта должен подтвердить:

- смысл `Checked`, назначение `Checkin` и `Checkout`; сейчас они сохраняются как наследуемые значения и не управляют возвратом, исправностью или сроком;
- смысл VIP и основания для отдельных исключений;
- действующий регламент сбора, набор, даты, ответственных и расписание приёма;
- владельца токена, Google-таблицы, первоначальных администраторов, политику хранения контактов;
- размещение новых полей O:AO вне легенды L:N и проверку на копии таблицы.

Ни один отсутствующий срок, год поступления, Telegram ID или дата события не восстанавливается предположением. Пока ответы не получены, работайте на синтетических данных; реальную кампанию не запускайте.

Проверка таблицы перед записью обнаруживает уже сделанные ручные правки, однако не исключает правку в последний момент между чтением и записью.
