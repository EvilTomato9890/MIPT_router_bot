# MIPT_router_bot

Telegram-бот учёта роутеров общежития № 7 на **Python 3.13**. Один процесс, отдельный файл SQLite с карточками, выдачами, историей, правами и заданиями. Google Sheets — редактируемое представление текущего учёта.

**Таблица использует только существующие A:J. Новые столбцы, служебные ID и листы не добавляются. Комплектации и выбора типа помещения в приложении нет.** Место — произвольный текст, например «101», «Клуб 7ки» или «КДС 7ки».

Реальные Telegram и Google API из приложения пока не проверены: токен бота и ключ сервисного аккаунта не предоставлены. Проверки используют синтетические данные. Исходная таблица при разработке не изменялась.

## Возможности

- Личные чаты и права по числовому Telegram user_id: администратор, оператор, наблюдатель; отзыв действует на диалоги и старые кнопки. Последний администратор защищён.
- Карточки с постоянным UUID в SQLite, уникальный инвентарный номер, модель, серийный номер, MAC, отдельное техническое состояние, VIP, поиск и фильтры.
- Выдача, физический возврат, продление, связанная передача и замена, утрата, обнаружение, ремонт, списание, инвентаризация неизвестного оборудования.
- Отдельная история каждой выдачи и журнал событий. Исправление добавляет корректирующее событие; зависимые события блокируют слепой откат.
- Подтверждение операций, проверка актуальной версии, транзакции SQLite и подавление повторных запросов.
- Исходящая очередь в Sheets, защита ручных правок, `/sync` с предварительным просмотром и трёхсторонним сравнением.
- `/repair_colors` восстанавливает только распознанные правила A2:J и сохраняет Checked и чужое оформление.
- Один активный ежегодный сбор, список несданного, примечания, явные исключения и одна ежедневная сводка ответственным. Прошлые сборы сохраняются в архиве.
- Короткая выдача: получатель, набор при участии в сборе, контакт, место и срок. Известный Telegram ID подставляется автоматически; неизвестный можно указать вручную или передать карточкой контакта.
- Незавершённые команды сохраняются при выходе в меню, сбое и перезапуске. `/resume` продолжает ввод, `/cancel` явно отменяет его и закрывает прежнее подтверждение.
- Отчёты, выдачи за период отдельно от числа устройств, безопасный CSV, резервные копии и восстановление.

## Быстрый запуск

Закреплён **Python 3.13.18**, зависимости и их контрольные суммы — в `uv.lock`, `requirements.txt` и `requirements-dev.txt`. Node.js не требуется.

С [uv](https://docs.astral.sh/uv/getting-started/installation/):

```sh
uv sync --frozen
uv run --frozen python -m ruff check .
uv run --frozen python -m ruff format --check .
uv run --frozen python -m pytest -q
uv run --frozen python -m router_bot demo
```

Без uv, из каталога репозитория:

```sh
python -m venv .venv
```

Активируйте `.venv` (`.venv\Scripts\Activate.ps1` в PowerShell или `source .venv/bin/activate` в Linux/macOS), затем:

```sh
python -m pip install --require-hashes -r requirements-dev.txt
python -m pytest -q
python -m router_bot demo
```

Демо работает в памяти и не обращается к настоящим Telegram / Google. Для постоянной работы достаточно `requirements.txt`; инструменты проверки отдельно находятся в `requirements-dev.txt`.

## Настройка настоящего бота

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN` и `BOOTSTRAP_ADMIN_ID` постоянным числовым ID. Username не подходит.
3. `DB_PATH` указывает на **отдельный файл базы**, по умолчанию `./data/router-bot.sqlite`. История не хранится в Google Sheets и не попадает в Git. Для сервера можно указать отдельный постоянный каталог вне исходников.
4. Сначала оставьте `SHEETS_MODE=disabled` и используйте тестовую БД. Запустите `python -m router_bot`, откройте личный чат и отправьте `/start`.
5. В «Настройки → Доступ» назначьте сотрудников. Получатели напоминаний должны открыть чат с ботом.
6. Подключите Google по [инструкции](docs/GOOGLE_SHEETS.md), сначала на копии таблицы. Новых столбцов для подключения не требуется.

Режимы: `disabled` сохраняет операции и ожидающую отправку в SQLite; `memory` явно помечает временную демонстрационную таблицу; `google` использует настоящий API.

Команды: `/menu`, `/resume`, `/cancel`, `/back`, `/help`, `/find текст`, `/list`, `/reports`, `/collection`, `/export`. Администратор: `/settings`, `/sync`, `/repair_colors`. Существенные изменения подтверждаются итоговым экраном. Меню сохраняет ответы; отмена до подтверждения не меняет учёт. Передача, замена, списание и администраторские действия находятся в «Дополнительно» карточки.

Откат остаётся универсальным для последних изменений карточки и выдачи, включая связанную замену двух роутеров: обе стороны откатываются одной транзакцией. Контакты восстанавливаются из закрытых снимков в SQLite; журнал не переписывается. Зависимые последующие события блокируют откат. Создание карточки и первичный импорт без предыдущего состояния не удаляются откатом; у старых замен без связанных снимков требуется предметное исправление.

В колонке I сохраняются контакт, @ник и известный ID в виде `tg://user?id=123456789`. Новых столбцов нет. Автоподстановка использует сведения, полученные от Telegram, или ранее подтверждённую сотрудником пару @ник/ID. Bot API не разрешает произвольный поиск числового ID человека по @нику: неизвестный ID не выдумывается. Фоновая синхронизация Google не задерживает подтверждение сохранённой операции.

## Переход с прежней версии

Остановите прежний процесс, сохраните старый `DB_PATH` и `.env`, установите Python-зависимости и запускайте новую версию с тем же путём к базе. Перед первым преобразованием непустой базы автоматически создаётся `backups/before-python-*.sqlite`.

Сохраняются UUID, роли, выдачи, первоначальный журнал, кампании, отметки отправки, очередь и идентификаторы повторных операций. При переходе с Node старые незавершённые диалоги сбрасываются один раз из-за несовместимости движков. При обновлении Python-версии ответы сохраняются и адаптируются к короткому диалогу. Среди прежних одновременно активных сборов остаётся последний созданный; остальные сохраняются как завершённые. Удалённые из текущей модели поля больше не используются; прежние исторические события не переписываются. Если старая версия уже добавила служебные колонки, Python-бот их игнорирует и не удаляет чужие данные автоматически.

Совместимость проверяется на синтетической базе, созданной настоящей предыдущей Node-версией, включая историю, кампанию, отправленное напоминание, снимок таблицы и повтор старого запроса.

## Что подтвердить до эксплуатации

Смысл Checked, Checkin/Checkout и VIP; регламент, даты и ответственных за сбор; владельца доступа и секретов; срок хранения контактов. До уточнения Checked и G/H сохраняются как наследуемые данные и не определяют исправность, плановый срок или факт возврата.

Дополнительные поля — техническое состояние, VIP, раздельные контакты, даты выдачи / срока / возврата и набор — хранятся в SQLite. Администратор уточняет старую выдачу в её карточке. Организации и выдачи без подтверждённого участия в сборе автоматически в кампанию не включаются.
