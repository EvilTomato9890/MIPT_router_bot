# Проверки и ограничения

## Локальные результаты

На Windows выполнены **45 автоматических тестов** в двух средах: Node.js 24.22.2 / SQLite 3.53.4 и Node.js 24.12.0 / SQLite 3.50.4. Использован npm 11.6.2; точная установка по lock-файлу проверена отдельно. Команды:

```sh
npm ci
npm run check
npm test
npm run demo
npm audit --omit=dev
```

На момент сдачи автоматические тесты проходят, синтаксис всех модулей проверен, демонстрационный цикл завершён. Проверка зависимостей не нашла известных уязвимостей. Точный итоговый счётчик тестов печатает `npm test`; CI повторяет проверки при push / pull request без секретов.

Тесты Google проверяют форму реальных HTTP-запросов с подставленным клиентом, RAW-запись, координаты и конфликт перед записью. Они **не являются проверкой доступности настоящего сервиса**. Тест формул проверяет построенные правила, ссылки и приоритеты; он не запускает вычислитель Google Sheets и не подменяет фактическую визуальную проверку.

## Что нужно проверить с настоящими подключениями

Используйте отдельного тестового бота, БД и копию таблицы; текущие реальные роутеры ради теста не меняйте.

1. Сервисный аккаунт читает копию, точно находит «7ка» и не получает доступ к лишним файлам. `/provision` добавляет только свободную согласованную O:AO; при занятых колонках останавливается.
2. Первый `/sync` показывает актуальные данные и ID закрепляются в правильных строках после подтверждения. Повтор не дублирует записи. Неполные исходные поля не заполняются предположением.
3. Два тестовых сотрудника проходят полный цикл, отозванный пользователь теряет доступ, в группе ничего не раскрывается. Получение сообщения требует предварительного `/start` сотрудника.
4. Отключение доступа Google / временный сбой сохраняют операции, затем очередь доходит без дублей. Сортировка и ручные изменения до подтверждения останавливают опасную запись; `/sync` разрешает расхождение.
5. `/repair_colors` на копии сохраняет Checked и чужие правила. Вручную меняйте только тестовые записи через все статусы, включая `?` и «Неизвестно»; проверьте заголовок, пустую строку, новую строку, VIP и новую границу сетки.
6. Для тестовой действующей выдачи заполните подтверждённый срок AD и TRUE в AE: проверьте обычный цвет в день срока и красный после смены московского дня / пересчёта HOUR. Свободные, неизвестные, утерянные и списанные не должны краснеть от старой даты. Сочетание с прежним правилом Checked отдельно осмотрите в интерфейсе Google.
7. Напоминание приходит только назначенным уполномоченным сотрудникам в заданное время; возврат, продление и смена ответственного обновляют отправки. После перезапуска нет пачки пропущенных сообщений.
8. Восстановите резервную копию в отдельный путь и сверяйте изменения с таблицей до включения отправки. Проверьте передачу полномочий и доступность секретов новому владельцу.

## Честные границы первой версии

- Запись в настоящий Telegram / Google не выполнялась: не предоставлены токен и ключ приложения, не подтверждены значения наследуемых дат / Checked, VIP, регламент и владельцы доступа.
- Предлагаемая O:AO требует согласования. Автоматического переноса занятых колонок или перестройки исходной таблицы нет; сначала нужна выделенная область / копия.
- Для `Checkin` / `Checkout` нет автоматического переопределения назначения. Подтверждённые даты ведутся в новых раздельных полях; нормальный импорт умеет жить с неизвестными датами.
- Предварительный просмотр пропускает спорные или неполные переходы вместо выдумывания фактов. Физический приём, обнаружение после утраты и списание требуют предметного действия в карточке. Подмена UUID и изменение постоянного номера разбираются вручную, новый роутер автоматически не создаётся.
- В SQLite действия атомарны, включая журнал и outbox. Google и SQLite не имеют общей транзакции и Sheets не даёт используемому клиенту атомарного compare-and-swap. Последняя одновременная правка / сортировка всё ещё возможна; обнаруженные расхождения блокируются и требуют повторного сравнения.
- У Telegram sendMessage нет ключа идемпотентности для отправителя. После успешного ответа логическое напоминание не повторяется, но таймаут после фактической доставки и падение между доставкой и фиксацией могут дать дубль. Сбой никогда не меняет статус роутера.
- Входящие update_id помечаются перед обработкой, чтобы повтор не продвигал диалог дважды. Падение непосредственно после принятия обновления может потребовать заново открыть шаг / нажать подтверждение. Итоговая операция привязана к сохранённому черновику и повторно проверяет версию / права.
- Напоминания агрегируются по кампании: не более одной подтверждённой сводки в московский день сотруднику; после простоя выбирается текущий этап, не все пропущенные.
- Формулы цветов проверены структурно для en_GB/en_US. Фактические цвета, локаль, сочетание с Checked и переход дня должны быть приняты на тестовой копии Google.
- Приложение рассчитано на один процесс и небольшую таблицу. Поиск просматривает текущий небольшой набор в памяти, JSON-поля не предназначены для аналитики миллионов выдач. Веб-панели, микросервисов и студенческого кабинета нет.
- При удалении роли пользователю нельзя «забрать» уже доставленное старое сообщение Telegram или скачанный CSV. Новое чтение / действие запрещается сразу; сотрудники сами соблюдают правила хранения полученных данных.
