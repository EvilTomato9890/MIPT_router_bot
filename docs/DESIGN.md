# Сценарии и модель

## Принятые допущения

Пользуются только уполномоченные сотрудники в личных чатах Telegram. Студенческого кабинета, обязательной регистрации студентов и рассылки студентам нет. VIP — независимый признак, не исключение из возврата. Кампанию и её календарь задаёт администратор; конец первого курса не вычисляется автоматически. ФИО и username не дают прав и не являются уникальными идентификаторами человека. Этаж не выводится из номера комнаты.

## Сценарий работы

Сотрудник находит карточку, выбирает действие, последовательно вводит данные, проверяет итог и подтверждает. При подтверждении снова проверяются роль, текущая версия и допустимость операции. SQLite в одной транзакции фиксирует оборудование, выдачи, событие и задание отправки в Sheets. Дальше очередь отправляет актуальное представление. Только подтверждённое чтением обратно обновление даёт сообщение об успехе Sheets.

Изменения в самой таблице поступают в бот по явному `/sync`: чтение → предварительный просмотр → разбор конфликтов → повторное чтение и проверка версий → транзакция. Незавершённый диалог или отменённый просмотр не выполняют предметных операций.

## Точное сопоставление A:J

| Колонка | Точный заголовок | Модель / правило                                                                                                           |
| ------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| A       | `Inv. №`         | `router.inventory`, постоянный уникальный номер, без перенумерации                                                         |
| B       | ` MAC Address`   | `router.mac`, нормализация разделителей и регистра, сохранение уникальности                                                |
| C       | `Place`          | `loan.place` либо `router.storage`; наследуемый текст помечается неподтверждённым                                          |
| D       | `Status`         | «Свободен» → stored; «Выдан» / «Просрочен» → issued; «Утерян» → lost; `?` / «Неизвестно» → unknown; «Списан» → written_off |
| E       | `Checked`        | `router.legacy.checked`, отдельное неизвестное по смыслу булево значение                                                   |
| F       | `Owner`          | Получатель наследуемой действующей выдачи; вне неё — неподтверждённая наследуемая пометка, не новая выдача                 |
| G       | `Checkin `       | `router.legacy.checkin`, без предположения о назначении даты                                                               |
| H       | `Checkout`       | `router.legacy.checkout`, не плановый срок и не доказательство возврата                                                    |
| I       | `Сontacts`       | Исходный текст и раздельные телефон / Telegram; user_id только подтверждённый                                              |
| J       | `Комментарий`    | `router.note`, не источник автоматического создания выдач или утрат                                                        |

Пробелы B/G и кириллическая «С» в I проверяются точно. Заголовки никогда не «исправляются» молча. Колонки K:N не пишутся. Пустая строка с одним FALSE не становится роутером. Статус определяется значением, а не цветом. На хранении при экспорте отображается «Свободен».

Первоначально все импортированные технически непроверенные записи получают «Нужна проверка», комплект неизвестен. Место `Клуб 7ки` или `КДС 7ки` остаётся текстом, его тип по умолчанию «Другое», достоверность `legacy`. Известная по заданию организация «Студсовет ФПМИ» распознаётся как организация; остальные неразмеченные получатели получают тип unknown до уточнения. Новые выдачи требуют явного выбора человека или организации.

## Хранение

`migrations/001_initial.sql` создаёт схему с версией. Поля карточек и выдач сериализуются в JSON для простой эволюции необязательных сведений; идентичность, уникальность, статус, техническое состояние и наличие действующей выдачи дополнительно проверяются SQLite.

| Сущность                     | Содержание                                                                                                                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| routers                      | UUID, уникальный инвентарный, модель, серийный, MAC, статус и состояние, VIP/смысл, комплект, хранение, наследуемые поля, версия, createdAt/updatedAt                                                                                                             |
| loans                        | Свой UUID, роутер, open, отдельный recipient.id, тип/ФИО/организация/ответственный, контакты, группа/набор/год, место, дата выдачи, подтверждённый срок, сотрудник, комплект/состояние при выдаче, фактический возврат/принявший/результат, связи передачи/замены |
| roles                        | Постоянный Telegram user_id и роль; не импортируется из учётных ячеек                                                                                                                                                                                             |
| events                       | ID, время записи, user_id подтвердившего сотрудника, объект, действие, до/после, причина, correction_of                                                                                                                                                           |
| requests                     | Ключ операции, автор, хеш запроса, результат для идемпотентного повтора                                                                                                                                                                                           |
| snapshots / conflicts        | Последний согласованный снимок полей и неразрешённые расхождения                                                                                                                                                                                                  |
| outbox                       | Актуальная версия карточки, группа связанной операции, состояние и задержки повторов                                                                                                                                                                              |
| drafts / sessions            | Предварительные просмотры и диалоги с владельцем и сроком 30 минут                                                                                                                                                                                                |
| campaigns / campaign_members | Календарь, ответственные, критерий набора, включения, действия, порядок, исключения; возвращённые остаются в отчёте                                                                                                                                               |
| reminders / settings         | Логические задания отправки, результаты и конфигурация / состояние опроса Telegram                                                                                                                                                                                |

Частичный уникальный индекс по `loans.router_id WHERE open=1` и `BEGIN IMMEDIATE` защищают выдачу, в том числе при двух соединениях. Все существенные изменения версионируются. Номер строки таблицы используется лишь как координата последнего чтения, перед записью проверяется заново.

Журнал запрещено менять / удалять триггерами через обычные операции приложения. Он **не криптографически защищён**: владелец файла БД может изменить саму схему. Структурированные контакты исключаются из журнала, но остаются в приватных карточках, необходимых снимках сравнения и краткоживущих диалогах. Технические логи не содержат карточек, контактов, токенов или текстов ошибок внешних API.

## Переходы и ограничения

| Действие               | Условия                                                                       | Результат                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Добавление             | Новый инвентарный; MAC/serial после нормализации не совпадают с существующими | stored; явно указанное состояние либо needs_check                                                  |
| Выдача                 | stored + working, нет открытой выдачи; получатель, место, срок                | issued + новая историческая выдача                                                                 |
| Возврат                | Открытая выдача, сверенный номер, реальный физический приём, место хранения   | Закрытая выдача с фактической датой, stored; рабочее состояние только по результату проверки       |
| Продление              | Администратор, причина, более поздний срок                                    | Новая версия, старый и новый сроки в событии                                                       |
| Передача               | Исправное выданное устройство; новый получатель, срок, место, причина         | Прежняя выдача закрыта как transfer без вымышленного физического возврата, новая связана с ней     |
| Замена                 | Реальный приём старого, новый stored + working                                | Оба изменения одной транзакцией, связь выдач и единая группа отправки Sheets                       |
| Смена места            | Явный текст и тип                                                             | Меняется место той же выдачи / хранения                                                            |
| Утрата                 | Причина и подтверждение                                                       | lost; действующая выдача и последний получатель не стираются                                       |
| Обнаружение            | Зафиксированы место / человек                                                 | Факт в истории, статус ещё lost; администратор решает, оставить у получателя или физически принять |
| Неисправность / ремонт | Результат проверки, причина                                                   | Меняется только техническое состояние                                                              |
| Списание               | Администратор и причина; отдельное решение по открытой выдаче                 | written_off, без удаления карточки и без вымышленной даты возврата                                 |
| VIP                    | Администратор и объяснение                                                    | Независимый флаг, сроки и сбор сохраняются                                                         |
| Исключение             | Администратор, причина, дата пересмотра                                       | Приостановка участия до пересмотра, отдельная от VIP и утраты                                      |
| Исправление            | Администратор, ID исходного события и причина, нет зависимых событий          | Корректирующая запись; исходное событие и выдачи сохранены                                         |

Неизвестное оборудование не выдаётся: сначала инвентаризация, явное уточнение статуса и проверка. Для первой версии администратор может подтвердить хранение неизвестного через новые поля таблицы и `/sync`; поле Checked для этого не используется. Списанное оборудование и спорное обнаружение не восстанавливаются обычной ручной заменой Status.

Просрочка вычисляется для открытой выдачи с подтверждённым сроком; утратой она не становится. Неизвестный срок показывается как «Срок не определён». Организация не получает фиктивного года поступления. Предупреждения о совпадении ФИО / комнаты не вводят запрета на несколько роутеров в комнате и не сливают людей с одинаковыми именами.
