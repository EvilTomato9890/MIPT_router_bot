# Модель и правила

## Допущения

Пользуются только сотрудники в личных чатах Telegram. Рассылки студентам и обязательной регистрации студентов нет. Даты сбора задаёт администратор. VIP не отменяет возврат и не создаёт бессрочное пользование. ФИО / username не являются ключами человека и не дают прав. Этаж и секция задаются отдельно, не выводятся из номера.

Комплектации и типа помещения в текущей модели нет. Место хранится текстом с признаком достоверности: отсутствует, неизвестно, наследуемая неподтверждённая запись или подтверждено сотрудником. Это не классификация помещений. История и дополнительные данные находятся только в отдельном файле SQLite.

## Хранение

| Сущность SQLite | Содержание |
|---|---|
| routers | Постоянный UUID, уникальный инвентарный, модель, серийный, MAC, базовый статус, отдельное техническое состояние, VIP/смысл, хранение, примечание, наследуемые поля, версия и время |
| loans | Отдельный UUID выдачи, recipient.id, человек / организация / unknown для наследуемого получателя, контакты, группа и набор, место, дата выдачи, подтверждённый срок, фактический возврат, сотрудники, состояние при выдаче/приёме, связи передачи/замены, участие в сборе |
| events | ID, время записи, user_id подтвердившего сотрудника, объект, действие, до/после, причина и correction_of |
| roles | Числовой Telegram user_id и роль; не импортируются из учётных ячеек |
| requests | Ключ операции, автор, хеш запроса, сохранённый результат повтора |
| snapshots / conflicts / outbox | Последнее согласованное A:J, расхождения, актуальная версия и группа исходящей операции, состояние повторов |
| campaigns / campaign_members / reminders | Календарь, критерии, назначения, действия обхода, исключения, сохранённые задания и результаты отправки |
| drafts / sessions / settings | Приватные просмотры/диалоги с владельцем и сроком 30 минут; конфигурация и состояние процесса |

Схема `router_bot/migrations/001_initial.sql` совместима с прежним файлом SQLite. При переходе меняется текущая JSON-модель и сужаются снимки до A:J; первоначальные события не изменяются. Перед преобразованием создаётся отдельная резервная копия. База, WAL, секреты и копии не коммитятся.

`BEGIN IMMEDIATE`, уникальные индексы и частичный индекс `loans.router_id WHERE open=1` защищают от одновременной выдачи. Каждое подтверждение проверяет права и версии. Оборудование, выдачи, журнал и outbox меняются одной транзакцией. HTTP-запросы выполняются после неё.

Триггеры запрещают обычное изменение / удаление журнала. Это не криптографическая защита от владельца самого файла БД. Структурированные контакты исключены из событий; технические логи не содержат карточек, токенов, ключей и сырых ошибок API. Исходные свободные комментарии могут содержать личные сведения и также требуют контроля доступа.

## Источник и точное сопоставление

[Таблица «Копия РОУТЕРЫ»](https://docs.google.com/spreadsheets/d/1N6lyJS7-PZ_hunmjnY06-0tnEEeOaP0Ypn-yEVfooK4/edit?gid=966826055), только `7ка`, sheetId `966826055`. Структура повторно прочитана 07.11.2026; это дата проверки источника, а не утверждение об отсутствии изменений после неё. Приложение перед каждым обменом перечитывает метаданные. `2ка`, K и легенда L:N не управляются; любые существующие колонки после J не читаются и не записываются как данные бота.

| Колонка | Точный заголовок | Правило |
|---|---|---|
| A | `Inv. №` | Существующий уникальный номер, не перенумеровывается |
| B | ` MAC Address` | MAC с нормализацией разделителей и регистра |
| C | `Place` | Текст текущего места, названия общих помещений сохраняются |
| D | `Status` | Свободен / Выдан / Просрочен / Утерян / ? / Неизвестно / Списан |
| E | `Checked` | Наследуемое булево, смысл не подтверждён |
| F | `Owner` | Получатель действующей наследуемой выдачи; вне неё — неподтверждённая историческая пометка |
| G | `Checkin ` | Исходное значение, назначение даты не предполагается |
| H | `Checkout` | Исходное значение, не доказательство возврата и не плановый срок |
| I | `Сontacts` | Исходный контакт; телефон и Telegram разбираются отдельно в БД, user_id не угадывается |
| J | `Комментарий` | Текст, не автоматический источник выдач или утрат |

Пробелы B/G и кириллическая «С» в I проверяются точно. Строка с FALSE без номера не является роутером. Цвет и Checked не определяют состояние. «Свободен» отображает внутренний stored; ? и «Неизвестно» — unknown, недоступный к выдаче. Импорт не приписывает исправность: по умолчанию needs_check, а неизвестные даты остаются неизвестными.

Без служебного столбца постоянный UUID хранится только в SQLite. Связь с таблицей — по уникальному неизменяемому Inv. №. Координата строки не идентификатор: сортировка безопасна, перед записью номер ищется и сверяется заново. Если исчез старый номер и появился новый, бот не угадывает, переименование это или другое устройство: записи требуют разбора.

Известная по исходному заданию организация «Студсовет ФПМИ» распознаётся как организация. Остальные неразмеченные получатели имеют unknown до уточнения. Наследуемый Owner у свободного / неизвестного роутера не создаёт фиктивную выдачу. Время импорта отделено от неизвестной даты фактического события.

## Основные операции

| Действие | Условия / результат |
|---|---|
| Добавить | Уникальный инвентарный, проверка MAC/serial после нормализации; stored и выбранное состояние |
| Выдать | Только stored + working, нет открытой выдачи; человек / организация, место и подтверждённый срок; новая историческая выдача |
| Принять | Открытая выдача, сверенный номер, физический приём, место хранения; фактическая дата и сотрудник, stored, без проверки needs_check |
| Продлить | Администратор, причина, более поздний срок; прежний / новый срок остаются в журнале |
| Передать | Исправное выданное устройство, новый получатель и срок; связанное закрытие и открытие без вымышленного физического возврата |
| Заменить | Физический приём старого и доступный новый; обе стороны одной транзакцией и одной группой отправки |
| Изменить место | Меняется та же выдача / хранение, новая выдача не создаётся |
| Утрата | Причина; lost сохраняет открытую выдачу и последнего получателя, просрочка не становится утратой |
| Обнаружен | Сначала факт с местом / человеком; администратор решает, оставить у прежнего получателя или физически принять |
| Проверка / ремонт | Меняется отдельное техническое состояние с причиной |
| Списание | Администратор, причина и отдельное решение по незакрытой выдаче; история не удаляется и возврат не выдумывается |
| VIP / исключение | VIP независим; исключение оформляется отдельно с причиной и датой пересмотра |
| Уточнить выдачу | Администратор подтверждает тип получателя, контакты, группу / набор / дату и участие в сборе, не меняя получателя вместо передачи |
| Инвентаризация | Неизвестный роутер: номер, физическое наличие, место, состояние и причина; только после проверки можно выдать |
| Исправить | Последняя ошибочная операция без зависимых событий; корректирующая запись с причиной, исходное событие сохраняется |

Предупреждения о совпадении ФИО и комнаты не сливают разных людей и не вводят запрета «один роутер на комнату». Новые даты, техническое состояние, VIP и набор не занимают новые столбцы таблицы — их источник SQLite.
