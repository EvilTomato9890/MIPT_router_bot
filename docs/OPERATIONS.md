# Эксплуатация, история и восстановление

## Работа сотрудника

Наблюдатель читает и экспортирует, оператор добавляет / выдаёт / принимает, фиксирует утрату, обнаружение и техническое состояние, работает в очереди. Администратор управляет доступом, сроками, VIP, исключениями, списанием, уточнениями, исправлениями, кампаниями, импортом и раскраской.

В карточках место — текст, без типа помещения. Комплектация не учитывается. При приёме сверяйте номер, подтверждайте физическое наличие, осматривайте / проверяйте работоспособность и указывайте хранение. Без проверки ставьте «Нужна проверка». Такой возврат не станет доступным к выдаче, пока сотрудник явно не подтвердит исправность.

Для человека группа и набор необязательны, но не выдумываются. Для организации учебные поля не применяются, можно указать ответственного человека. Подтверждённый Telegram ID не ищется по username. Паспортные данные и пароли роутеров не собираются.

Старую выдачу администратор дополняет кнопкой «Уточнить выдачу»: тип получателя, раздельные контакты, набор, дата и явное участие в сборе. Имя при этом не заменяется: новый получатель оформляется передачей, чтобы сохранить обе выдачи.

Утрата сохраняет последнего получателя и незакрытый вопрос возврата. «Обнаружен» фиксирует факт, затем администратор решает, оставлен ли роутер у прежнего получателя или принят. Списание не означает физический возврат. Исправление последней ошибочной операции создаёт корректирующее событие; при зависимых событиях нужны предметные действия с причиной.

## Кампания сбора

Администратор задаёт набор / учебный год, начало, конечный срок, уполномоченных ответственных, место, часы и инструкцию. До запуска показывается список и неполнота.

Автоматически включаются только люди подтверждённого набора с явно подтверждённым участием этой выдачи в сборе. Для использования общим помещением выбирайте «Нет» при вопросе об участии; тип помещения не собирается и по названию ничего не угадывается. Организации, неизвестные наборы / получатели и неподтверждённое участие автоматически не включаются. Администратор может включить выдачу явно по номеру с причиной.

Очередь: просрочка, индивидуальный порядок, ближайшие сроки, отдельно заданные этаж / секция и естественная сортировка места. Фильтры по группе, месту и оператору. «Принят» открывает обычный диалог физического возврата. «Не застали», «Связались», «Предложена другая дата», «Проблема», «Следующий» не меняют срок или статус. Продление подтверждает администратор. Возвращённые исчезают из текущей очереди, но остаются в итогах.

Более поздний подтверждённый индивидуальный срок учитывается вместо конечной даты кампании. VIP сам по себе не исключает из сбора. Отдельное исключение действует до даты пересмотра; можно также явно исключить из конкретной кампании с причиной. В настройках кампанию можно приостановить.

Начальные интервалы уведомлений — 14, 7, 1, 0 дней, затем ежедневная сводка по просрочкам; это пример настроек, не регламент общежития. Время и интервалы в `.env`, зона Europe/Moscow. Получают только назначенные сотрудники с текущими правами и предварительным `/start`, студенты не получают рассылки. Задания и результаты хранятся в БД, после простоя выбирается один актуальный этап, не пачка пропущенных.

## Постоянная служба

Один процесс, постоянный диск и исходящий HTTPS к Telegram / Google. База отдельно по `DB_PATH`, например `/var/lib/mipt-router-bot/router-bot.sqlite`; секреты — у пользователя службы. Не используйте сетевую / облачно синхронизируемую папку для рабочей SQLite. Не запускайте две копии разных БД с одним токеном.

Файл `.lock` рядом с БД использует блокировку ОС и освобождается при завершении / падении процесса. Старую Node-службу остановите до миграции: её прежний механизм блокировки отличается.

Пример systemd после размещения репозитория в `/opt/mipt-router-bot`, создания `.venv` и отдельного системного пользователя `routerbot`:

```ini
[Unit]
Description=Dorm 7 router inventory bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=routerbot
WorkingDirectory=/opt/mipt-router-bot
ExecStart=/opt/mipt-router-bot/.venv/bin/python -m router_bot
Restart=on-failure
RestartSec=10
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

Каталоги данных, копий и ключей должны быть доступны только службе и назначенному ответственному. `.env` читается только из рабочего каталога; переменные окружения имеют приоритет. Для Windows запускайте один `python -m router_bot` из каталога проекта с активированной `.venv`; постоянный запуск можно настроить штатным планировщиком.

Если для токена уже есть webhook, приложение останавливается и не удаляет его самостоятельно. При согласованном переносе отключите webhook через Telegram deleteWebhook с `drop_pending_updates=false`, не публикуя токен в логах / истории общего терминала. Смена транспорта не должна удалять ожидающие обновления.

## Резервные копии отдельной БД

Раз в московский день создаётся согласованная копия через стандартный `sqlite3.Connection.backup`; по умолчанию хранятся 14 дневных копий. Копия проверяется `PRAGMA integrity_check`. Ошибка не меняет учёт, техническое предупреждение не содержит карточек.

```sh
python -m router_bot backup
python -m router_bot backup ./backups/before-upgrade.sqlite
```

Несуществующая исходная БД не превращается в «успешную пустую копию», путь копии не может совпадать с исходным. При работе не копируйте один `.sqlite` файловым менеджером: часть данных может быть в WAL. Резервные копии также содержат персональные данные и требуют закрытого хранения / отдельной копии на другом носителе. Снимок `before-python-*` перед миграцией хранится отдельно от ротации дневных копий до решения ответственного.

### Восстановление

1. Остановите службу и все процессы со старым / тем же токеном.
2. Сохраните повреждённые sqlite / wal / shm для разбора. Не удаляйте их вслепую.
3. Восстановите проверенную копию в новый путь, например `data/restored.sqlite`; укажите его в `DB_PATH`.
4. До запуска с Google выполните `python -m router_bot pause-sync`: исходящая очередь будет заблокирована и отмечена как требующая сравнения. Команда работает без токена, пока бот остановлен.
5. Сначала с `SHEETS_MODE=disabled` проверьте карточки, роли, историю и кампании. Затем включите google, выполните `/sync`, проверьте различия и явно согласуйте записи. Старую копию нельзя без сверки отправлять поверх более новой таблицы.
6. Сверьте последние события с внешним учётом, права и ответственных. Повторный полный импорт не заменяет восстановление исторических выдач.

Старая резервная копия содержит отметки доставки только на момент создания: сообщения, отправленные позднее, после восстановления могут повториться. Предметные операции имеют отдельные сохранённые ключи повторов.

## Контакты и передача полномочий

`CONTACT_RETENTION_DAYS` задаёт срок после закрытия выдачи отдельно от истории движения; начально 365 дней, 0 отключает автоочистку. Неизвестная дата не заменяется временем импорта, старые записи без даты требуют решения. Наследуемые контакты вне выдач тоже требуют разбора. Не помещайте контакты в причины / примечания, если рассчитываете на очистку только структурированных контактов.

История версий Google, комментарии, резервные копии и необходимые снимки конфликтов могут сохранять прежние сведения: владелец задаёт их сроки и доступ отдельно. После возврата и подтверждённого обмена текущая строка перестаёт показывать контакты получателя. Просмотры / диалоги удаляются через 30 минут.

При передаче создайте копию и проверьте восстановление. Назначьте нового администратора по числовому ID, он должен открыть чат и проверить административные команды. Передайте ключи / токен защищённым каналом, обновите владельцев сервисного аккаунта / таблицы / службы и ответственных кампаний. После проверки новый администратор отзывает прежнего. BOOTSTRAP_ADMIN_ID применяется однократно для новой БД и не возвращает отозванные права при перезапуске. Последнего администратора удалить нельзя.

При компрометации перевыпустите токен через BotFather, Google-ключ отзовите в Cloud; новые секреты задаются конфигурацией, новая БД для ротации не нужна.
