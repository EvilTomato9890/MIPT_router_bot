# Подключение Google Sheets

## Доступ

1. В Google Cloud создайте отдельный проект / сервисный аккаунт и включите Google Sheets API.
2. Создайте ключ сервисного аккаунта, положите JSON в `secrets/service-account.json` или иной закрытый каталог вне Git. Доступ к файлу — только у учётной записи процесса бота.
3. Дайте `client_email` из JSON право редактора **только нужной таблицы**, сначала её тестовой копии. Domain-wide delegation не нужен. Drive API и доступ к остальному диску приложению не требуются.
4. В `.env` задайте `SHEETS_MODE=google`, `SPREADSHEET_ID`, точные `SHEET_TITLE` / `SHEET_ID`, путь `GOOGLE_APPLICATION_CREDENTIALS`.
5. До первой записи проверьте источник командой `npm run inspect:sheets`: это только чтение структуры и агрегатов, без печати контактов.

OAuth scope `spreadsheets` технически не ограничивается одним Spreadsheet ID. Реальное ограничение достигается отдельным сервисным аккаунтом, которому расшарена только эта таблица, и фиксированным ID в конфигурации. Ключи, `.env`, рабочая БД и копии игнорируются Git.

## Согласованное расширение O:AO

Первая версия предлагает новые столбцы **после N**, не перемещая исходные A:J и легенду L:N. В исходном файле было 30 колонок; недостающие колонки добавляются только справа. Если в O:AO есть чужие данные, даже формула с пустым результатом, `/provision` останавливается. В этом случае владелец должен заранее выделить согласованную свободную область / копию; адаптер не перестраивает источник и не выбирает новую область автоматически.

После согласования установите `SHEETS_MAPPING_APPROVED=true`, в личном чате администратора вызовите `/provision` и подтвердите конкретное добавление заголовков. Без этого флага записи и изменение форматирования Google запрещены. Повтор `/provision` при правильных заголовках ничего не добавляет.

| Колонка | Заголовок / значение                                                       |
| ------- | -------------------------------------------------------------------------- |
| O       | `router_id` — неизменяемый UUID физического устройства                     |
| P       | Модель                                                                     |
| Q       | Серийный номер                                                             |
| R       | Техническое состояние — Исправен / Нужна проверка / Неисправен / В ремонте |
| S       | VIP — TRUE/FALSE                                                           |
| T       | Смысл VIP                                                                  |
| U       | Телефон                                                                    |
| V       | Telegram username, без @                                                   |
| W       | Подтверждённый Telegram ID; пусто, если неизвестен                         |
| X       | Тип получателя — person / organization / unknown (legacy)                  |
| Y       | `recipient_id` — идентичность получателя, не ФИО                           |
| Z       | Группа                                                                     |
| AA      | Год поступления                                                            |
| AB      | Учебный год                                                                |
| AC      | Дата выдачи (подтверждена), ISO ГГГГ-ММ-ДД                                 |
| AD      | Срок возврата (план), ISO ГГГГ-ММ-ДД                                       |
| AE      | Срок подтверждён — TRUE/FALSE                                              |
| AF      | Фактический возврат, ISO ГГГГ-ММ-ДД                                        |

Формульные ячейки обнаруживаются по `userEnteredValue.formulaValue`, а не по первому символу текста; бот сохраняет формулы и останавливает попытку изменить их результат. Все пользовательские строки отправляются с `valueInputOption=RAW`.

## Первый импорт

Используйте пустую тестовую БД и копию таблицы. Не добавляйте в неё руками роутеры, уже присутствующие в источнике, до импорта.

1. Перечитайте структуру, согласуйте схему, выполните `/provision`.
2. Вызовите `/sync`: будут показаны новые записи, все импортируемые значения, ошибки и неполнота. FALSE без инвентарного номера игнорируется. Строки без номера с другими данными требуют уточнения.
3. Пролистайте отчёт и подтвердите проверенные изменения. Только теперь создаются карточки и наследуемые выдачи.
4. Исходящая очередь закрепит UUID в O, сверяя исходные значения и уникальный Inv. №. После подтверждённого чтения обратно связь работает по UUID.
5. Повторный импорт не создаёт выдачи заново. Импорт без согласованной служебной области возможен в БД, но отправка будет блокироваться до подключения схемы.

MAC нормализуется, но инвентарные номера не перенумеровываются. `?` остаётся неизвестным, Checked не определяет исправность. Организации и неразмеченные наборы не попадают в студенческий сбор автоматически. Старый Owner у свободного / неизвестного роутера сохраняется как наследуемая пометка и не превращается в новую выдачу. При реальном возврате текущий получатель уходит из текущего представления в историю.

## Ручная работа и `/sync`

Сотрудники могут редактировать учётные поля в Sheets. Ограничений, запрещающих такие правки, бот не устанавливает. Завершите пакет правок, затем администратор выполняет `/sync`.

Сравниваются последний согласованный снимок, текущая БД и таблица. Правка только в таблице принимается после просмотра, только в боте — остаётся в отправке. Совпадающие изменения согласуются; независимые поля объединяются. Конкурирующие правки одного поля, контактного набора или связанного набора «статус / получатель / место / выдача / сроки» требуют решения. В отчёте можно выбрать таблицу, бота или исправленные значения и указать причину. Выбранное решение сначала сохраняется в просмотре, учёт меняется при применении набора.

Если редактируется I и отдельно U/V не менялись, телефон и Telegram разбираются из нового исходного контакта; при самостоятельной правке U/V используются они. Пустая ячейка внутри согласованной схемы — явная очистка; отсутствующая в схеме колонка не считается очисткой. Username никогда не превращается в Telegram user_id.

Смена получателя создаёт связанную передачу с сохранением предыдущего. Для новой выдачи нужны подтверждённые сведения, исправность, дата и срок. Ручной статус «Свободен» не заменяет физический приём: запись остаётся на уточнении, нужно оформить реальный возврат в карточке, затем заново сравнить состояния и выбрать проверенный вариант. Аналогично через карточку оформляются обнаружение после утраты и списание с причиной. Изменение контакта / комментария старой выдачи не требует выдумывать неизвестные даты и набор.

Перед применением заново читается таблица и проверяется полный набор версий БД. Если после просмотра что-то изменилось, нужен новый `/sync`. Неразобранные строки пропускаются с прежним снимком; опасные исходящие записи остаются заблокированными. Связанные замены не применяются наполовину. Старые задания заменяются актуальной версией.

Изменение / очистка UUID, спорное изменение инвентарного номера и дубли не создают новое устройство. Исчезновение строки не удаляет БД. Восстановите в таблице строку с прежними ID и инвентарным, затем вызовите `/sync`; если данные БД должны вернуться в таблицу, выберите их с причиной. Списание оформляйте отдельной операцией, не удалением строки.

## Защита исходящей записи и сбои

Изменение БД и outbox фиксируются одной транзакцией. При каждом повторе очередь читает запись в таблице и сравнивает с последним согласованным снимком; адаптер читает ещё раз непосредственно перед записью. Непринятые изменения блокируют затронутую запись / группу связанной замены, остальные устройства продолжают синхронизацию. Новые строки добавляются в свободные ячейки без перезаписи легенды или формул. При временной ошибке действует сохраняемая экспоненциальная задержка до часа; длительное ожидание вызывает сводку администраторам.

Запись значений обеих сторон замены выполняется одним Sheets values.batchUpdate. Общей транзакции с SQLite нет. После API-ответа значения читаются обратно и сравниваются. Если запись успела выполниться перед падением процесса, повтор распознаёт уже совпадающий результат и не добавляет вторую строку.

Google Sheets не предоставляет используемому API атомарного «сравнить и заменить» ячеек. Между последним чтением и записью остаётся узкое окно гонки, также возможна сортировка в этот момент. Поэтому для обычной работы заканчивайте ручные изменения до подтверждения. При обнаруженном расхождении заново выполняйте `/sync`, а при сомнениях сверяйтесь с историей версий Google и журналом SQLite. Абсолютная защита от всех одновременных редакторов не заявляется.

## Раскраска

`/repair_colors` доступна только администратору, показывает пропуски, дубли, формулы, диапазоны, приоритеты и необходимость пересчёта. Она управляет только помеченными правилами бота и распознанными исходными правилами `=$Dномер="статус"` для A:J. Остальные правила, включая исходное зачёркивание E=TRUE, сохраняются.

Шесть управляемых правил начинаются с A2:J, имеют открытый конец и исключают пустой инвентарный номер. Утерянное — голубовато-серое, свободное — зелёное, выданное — жёлтое, просроченное — красное, оба неизвестных — серое, списанное — отдельный фиолетовый фон с читаемым текстом. VIP хранится в S, не перекрывает основной цвет.

Просрочка имеет первый приоритет: явное D=«Просрочен» либо D=«Выдан», AE=TRUE и подтверждённая дата AD раньше TODAY(). Checkout не используется. Для автоматической смены дня просмотр отдельно предлагает пересчёт **HOUR для всей книги**, часовой пояс должен уже быть Europe/Moscow. Проверены формулы для локали исходника en_GB и en_US; другая локаль требует проверки на копии, автоматическое применение блокируется.

После подтверждения правила читаются обратно. Повторное восстановление без изменений не создаёт дубли; после первого согласованного восстановления процесс поддерживает этот набор автоматически. Ручная смена D меняет цвет средствами Sheets без `/sync`; данные бота обновляются только по `/sync`. На реальных роутерах не создаются тестовые статусы. Фактическую работу цветов, сочетание с наследуемым Checked и смену дня нужно проверить на отдельном тестовом листе / копии перед боевым подключением.
