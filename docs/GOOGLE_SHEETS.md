# Google Sheets без расширения таблицы

## Доступ и проверка

1. Создайте отдельный Google Cloud service account и включите Sheets API.
2. Дайте `client_email` право редактора только нужной таблицы, сначала тестовой копии. Domain-wide delegation и Drive API не нужны.
3. Сохраните JSON-ключ в закрытом `secrets/service-account.json` или вне репозитория. В `.env` укажите путь `GOOGLE_APPLICATION_CREDENTIALS`, `SHEETS_MODE=google`, ID файла, точное имя и sheetId.
4. Выполните `python -m router_bot inspect-sheets`: команда только читает структуру и агрегаты, не печатает контакты.
5. Вызовите `/sync` в личном чате администратора, просмотрите данные и подтвердите проверенный набор.

Scope `spreadsheets` не ограничивается одним файлом технически: используйте отдельный аккаунт, которому расшарена только нужная таблица, и фиксированный ID в конфигурации. Секреты и рабочая база не попадают в Git.

**Подключение не добавляет столбцы, заголовки, служебные UUID или листы. Команда `/provision` отключена.** Адаптер читает только существующие A:J целевого листа. Прямые записи ограничены A:J; добавление новых строк оборудования допустимо, добавление колонок и изменение заголовка запрещены. Легенда L:N, всё после J и лист «2ка» сохраняются.

## Что находится в таблице, а что в SQLite

В таблице остаются только исходные поля A:J из [сопоставления](DESIGN.md). Постоянные UUID, история, права, техническое состояние, VIP, модели / серийные, раздельные контакты, даты выдачи / срока / возврата, набор, кампании и задания находятся в отдельной SQLite.

G/H сохраняются без нового толкования. Подтверждённые даты задаются в карточке бота. Старую выдачу администратор дополняет через «Уточнить выдачу», срок — через «Продлить срок». Новых столбцов для этих сведений нет. Прямая правка I обновляет исходный контакт и разбор телефона / username в БД; подтверждённый user_id по username не подбирается.

## Первый импорт

Сначала используйте отдельную БД и копию таблицы. `/sync` показывает новые записи, неполноту, ошибки и различия. До подтверждения учёт не меняется. FALSE без номера игнорируется, ? импортируется как неизвестное, Checked не делает роутер исправным / возвращённым. Наследуемые даты и принадлежность к набору не выдумываются.

Повтор не создаёт дубли. Если такой номер уже есть в локальной БД, но согласованного снимка ещё нет, администратор должен явно выбрать проверенный вариант таблицы / бота с причиной. Уникальный Inv. № остаётся привязкой к тому же UUID в SQLite. Пара «исчез старый номер / появился новый» требует исключить переименование, а не автоматически создать второе устройство.

## Ручные правки и `/sync`

Сотрудники могут редактировать учётные поля непосредственно в таблице. Бот не устанавливает запрещающие это ограничения. Завершите пакет правок, вызовите `/sync`, пролистайте различия и подтвердите.

Сравниваются последний согласованный снимок A:J, текущая таблица и текущее представление БД. Только таблица изменилась — предлагается импорт; только бот — сохраняется ожидающая отправка. Совпадающие результаты согласуются. Независимые поля объединяются; разные правки одного поля и несовместимые изменения статуса / получателя / места показываются как конфликт.

Для конфликта доступны значения таблицы, бота или исправление отдельных полей с причиной. Решение сначала сохраняется в просмотре, применяется после подтверждения всего проверенного набора. Неразобранные записи пропускаются, сохраняют прежний снимок и блокировку опасной исходящей записи. При изменении таблицы или версий БД после просмотра требуется новый `/sync`.

Пустая ячейка в прочитанном A:J — явная очистка. Поля, вообще отсутствующие в A:J, не очищаются: технические данные, сроки и набор продолжают жить в SQLite. Правка контакта / примечания старой выдачи не требует заполнять неизвестные даты.

Смена Owner или Status не должна обходить факты выдачи / возврата. Если переход требует недостающих сведений, строка остаётся на уточнении: оформите выдачу, передачу, физический приём, обнаружение или списание в карточке бота, затем снова сравните и согласуйте состояния. Бот не потеряет прежнего получателя простой перезаписью F. Прямой статус «Свободен» не доказывает физический возврат.

Удаление строки не удаляет карточку, выдачи и историю. Восстановите строку с прежним Inv. № и повторите сравнение. Не меняйте постоянный номер ради сортировки; номер строки не идентификатор. Списание оформляется с причиной, а не удалением строки.

## Исходящая очередь и сбои

Учёт и outbox записываются одной транзакцией SQLite. Затем бот перечитывает затронутые значения и сравнивает их с согласованным снимком. Перед HTTP-записью адаптер читает строку ещё раз, ищет её по Inv. № и проверяет актуальные значения. Непринятые ручные правки блокируют только затронутую запись / группу связанной замены. Остальные устройства продолжают обновляться.

Пользовательские строки передаются как RAW, не формулы. Формулы определяются по `userEnteredValue.formulaValue`; чужая формула не заменяется её вычисленным результатом. Новые записи не занимают ячейки с формулами, даже если результат пуст.

После ошибки задача остаётся с сохраняемой задержкой повтора, при длительном ожидании уведомляются администраторы. После успеха значения читаются обратно. Сообщение об обновлённой таблице появляется только после подтверждения. Если запись успела пройти перед падением, повтор обнаруживает уже совпадающее значение и не добавляет вторую строку.

Google и SQLite не имеют общей транзакции. Между последним чтением и записью Sheets остаётся окно для одновременной правки / сортировки. Поэтому закончите ручное редактирование до подтверждения. Обнаруженный конфликт пересматривается; абсолютная защита от всех одновременных редакторов не заявляется.

## Раскраска и просрочка

`/repair_colors` сначала показывает отсутствующие / дублирующиеся правила, неверные диапазоны, ссылки и приоритеты. Управляются только распознанные прежние статусные правила A:J и правила с меткой бота. Сохраняются Checked и всё постороннее оформление.

Управляемый диапазон — A2:J с открытым концом, непустой инвентарный обязателен. Свободен — зелёный; Выдан — жёлтый; Просрочен — красный; Утерян — голубовато-серый; ? / Неизвестно — серый; Списан — отдельный фиолетовый. VIP хранится в БД и не перекрывает статус. Повторное восстановление не создаёт дубли, правила читаются обратно.

Ручная смена D меняет цвет средствами самой таблицы без `/sync`; данные бота обновляются отдельно. Формулы используют только A и D, не Checked и не даты G/H. Проверены построение правил для en_GB/en_US; другую локаль нужно принять на копии.

Подтверждённый срок хранится в SQLite. После смены московского дня бот ставит в очередь обновление D=«Просрочен» для действующей просроченной выдачи, сохраняя внутренний статус issued. Утерянное / неизвестное / свободное не становится просроченным от старой даты. **При остановленном боте или недоступном Google новое вычисленное значение D придёт после возобновления обмена:** без дополнительных столбцов / подтверждённого значения G/H таблица сама не вычисляет скрытый срок из SQLite.

Визуальную работу правил, сочетание с Checked и смену дня нужно проверить на отдельной тестовой копии. Реальные роутеры ради проверки не меняются.
